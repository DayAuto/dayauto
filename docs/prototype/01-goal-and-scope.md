# 01. 목표와 범위

## 1. 시연 시나리오 (11/30 월요일 기준)

2026-11-30은 **월요일**이다. 주간 배정이 "이번 주(월~일)" 단위이므로 시연 당일 한 주 전체가 남아 있어 시나리오가 가장 잘 보인다.

| 단계 | 사용자 행동                                                                                              | 화면에 보여야 하는 것                                                                                                |
| ---- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 0    | (사전) 구글 로그인, 생활 시간대 입력, 목표 2개 등록 완료 상태                                            | 주간표에 토익·산업안전기사 학습 블록이 마이크로/집중 슬롯에 배치되어 있음. 회사 일정은 회색 블록으로 함께 보임       |
| 1    | 구글 캘린더(별도 탭)에 "팀 회식 19:00–23:00"을 오늘 날짜로 추가 (퇴근 후 집중 슬롯 20:00–23:00을 덮도록) | —                                                                                                                    |
| 2    | DayAuto에서 **[동기화]** 클릭                                                                            | "새 일정 1건, 학습 일정과 겹침 N건" 안내 + 우측 패널에 **조정안 카드** 표시                                          |
| 3    | 조정안 카드 확인                                                                                         | 사유 한 줄 + 이동 목록(예: `[산업안전기사] … · 월 20:00 → 화 20:45`) + **[이대로 진행] [다시 배분] [원래 일정대로]** |
| 4    | (선택) [다시 배분] 클릭                                                                                  | 다른 시간대로 옮기는 새 조정안이 카드에 교체 표시                                                                    |
| 5    | [이대로 진행] 클릭                                                                                       | 주간표의 해당 블록이 제안된 시간으로 **이동**. 카드는 "반영 완료"로 바뀌고 사라짐                                    |
| 6    | (보조) 회식 일정을 구글에서 삭제 후 [동기화]                                                             | 일정 삭제가 감지되었다는 안내만 표시 (프로토타입은 되돌림 제안 없음)                                                 |

## 2. 범위

### 2.1 완결 기능 (반드시 끝까지 동작)

충돌 감지 → 재배분안 생성 → 3택 제시 → 승인 반영

- 모든 충돌을 **제안 경로**로 처리한다. 중요도 분기(고/저중요도)와 자동 반영은 하지 않는다.

### 2.2 지원 기능 (완결 기능을 돌리기 위한 최소 구현)

| 기능                    | 축소 방식                                                                        |
| ----------------------- | -------------------------------------------------------------------------------- |
| 구글 로그인·캘린더 읽기 | 단일 계정, `calendar.events.readonly` 읽기 전용, **[동기화] 버튼 시점에만 조회** |
| 생활 시간대 입력        | 설문 없이 직접 입력                                                              |
| 목표 등록·태스크 생성   | 시드된 종목·회차 중 선택. 커리큘럼은 DB 시드(샘플 JSON)에서 복사                 |
| 긴급도 산출·주간 배분   | 04 문서의 기본 산식만                                                            |

### 2.3 제외 (12월 이후) — 구현하지 말 것

적합성 판단(FA 전체), 패턴학습(PL 전체), 온보딩 설문(OB-06/07), 온보딩 재개(OB-09), 연동 실패 대응 화면(OB-03~05), 분해 결과 조정(GD-05), 미지원 종목(GD-08), 가용 초과 조정안(RA-06), 다중 목표 현황 상세(RA-08), 중요도 분기·자동 반영·사후 확인·되돌리기(ES-03, ES-07~09), 무응답 처리(ES-06), 보관함(ES-10~12), 통지 시점 분기·배치(ES-02, Vercel Cron), 웹훅(OB-02 주 경로), 이메일(Resend), 챗봇·AI SDK·SSE, 런타임 LLM, PostHog/Sentry 실제 연동, 토큰 암호화 저장(SC-02), 완료/미완료 체크 UI, 다음 주 이동 UI.

> 완료/미완료 체크, 주 이동 같은 "있으면 좋은 것"도 넣지 않는다. 시연 동선과 무관한 기능은 디버깅 대상만 늘린다.

## 3. 요구사항 ID 매핑

| 요구사항                    | 프로토타입 구현 수준                                                              |
| --------------------------- | --------------------------------------------------------------------------------- |
| REQ-OB-01 캘린더 읽기 연동  | 구글 로그인 시 readonly 스코프 요청. 쓰기 없음                                    |
| REQ-OB-02 캘린더 동기화     | **[프로토 한정] 웹훅·폴링 대신 [동기화] 버튼 시 이번 주 일정 재조회 후 비교**     |
| REQ-OB-08 생활 시간대 입력  | 4개 구분 시간대 입력, 최소 1개, 15분 단위                                         |
| REQ-GD-01 목표 등록         | 시드 종목 드롭다운 + 미래 회차만 선택                                             |
| REQ-GD-02/03/04 태스크 생성 | 커리큘럼 단원 → 태스크 복사, 유형별 슬롯·청크 범위 규칙 부여                      |
| REQ-RA-01 긴급도            | 기본 산식 (04 문서 §3)                                                            |
| REQ-RA-03/04/07 배분        | 주간 배분 (04 문서 §4). 단일 목표 시 비교 생략은 산식상 자동 충족                 |
| REQ-RA-05 재배분안          | 제안 상태로 생성 (DB의 배정은 미변경)                                             |
| REQ-ES-01 변경 감지         | **[프로토 한정] 동기화 시 추가·변경·삭제 식별, 추가·변경만 겹침 검사**            |
| REQ-ES-04 3택 제시          | 사유 한 줄 + 3버튼                                                                |
| REQ-ES-05 3택 처리          | 수락=반영 / 다시 배분=다른 안 재생성 / 원래대로=미반영                            |
| REQ-CP-02, REQ-DT-01/02/03  | UTC 저장·date-fns-tz, 15분 정수 청크, 결정론, LLM 실행 권한 없음(애초에 LLM 없음) |
| REQ-SC-01                   | readonly 스코프만. 일정은 제목·시작·종료 + 식별/비교용 메타데이터만 저장          |
