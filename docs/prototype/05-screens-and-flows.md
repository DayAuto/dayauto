# 05. 화면과 흐름

PC 웹 기준 (1280×720 이상). 한국어 UI. 디자인은 shadcn/ui(Base UI) 기본 스타일로 깔끔하게만 — 시각적 완성도보다 **시연 동선이 끊기지 않는 것**이 우선이다. 벤치마크: Reclaim.ai(좌 캘린더 / 우 패널).

## 1. 라우팅과 진입 분기

| 경로             | 접근 조건 | 내용                                    |
| ---------------- | --------- | --------------------------------------- |
| `/login`         | 비로그인  | 서비스 한 줄 소개 + [Google로 시작하기] |
| `/setup/windows` | 로그인    | 생활 시간대 입력                        |
| `/setup/goals`   | 로그인    | 목표 등록·삭제                          |
| `/`              | 로그인    | 메인 (주간표 + 우측 패널)               |

`/` 진입 시 분기: 비로그인 → `/login` / 시간대 0개 → `/setup/windows` / 활성 목표 0개 → `/setup/goals` / 그 외 메인.
메인 상단에 [시간대 수정] [목표 관리] 링크를 둔다.

## 2. 로그인 (`/login`) — REQ-OB-01

- Google provider 스코프: `openid email profile https://www.googleapis.com/auth/calendar.events.readonly`
- `authorization.params`: `access_type: "offline"`, `prompt: "consent"`
- 로그인 직후 첫 동기화는 하지 않는다 (메인에서 [동기화] 또는 메인 최초 진입 시 1회 자동 실행 — 아래 §5).

## 3. 생활 시간대 입력 (`/setup/windows`) — REQ-OB-08

- 4개 구분 카드: 출근 / 점심 / 퇴근 / 퇴근 후. 각 카드에 [사용] 토글, 시작·종료(15분 단위 select), 요일 체크박스, 슬롯 유형(마이크로/집중) 선택.
- **기본값 (시연 편의, 사용자가 수정 가능)** **[가정 D-09]**:

| 구분    | 시간        | 요일  | 슬롯     | 청크 |
| ------- | ----------- | ----- | -------- | ---- |
| 출근    | 07:30–08:15 | 월~금 | 마이크로 | 3    |
| 점심    | 12:30–13:00 | 월~금 | 마이크로 | 2    |
| 퇴근    | 18:30–19:15 | 월~금 | 마이크로 | 3    |
| 퇴근 후 | 20:00–23:00 | 월~금 | 집중     | 12   |

- 검증: 사용 중인 시간대 최소 1개 / 시작 < 종료 / 15분 단위 / 요일 최소 1개 / **같은 요일에 시간대끼리 겹치지 않음**. 실패 시 필드 아래 문구.
- 저장 = 사용자의 시간대 전부 교체(delete + create). 저장 후 이번 주 재배분(04 §4.1) 실행 → 목표가 없으면 `/setup/goals`, 있으면 `/`로 이동.
- 한 구분당 1개 행만 입력받는다 (요일별 다른 시각은 프로토타입 제외).

## 4. 목표 등록 (`/setup/goals`) — REQ-GD-01, GD-02

- 등록 폼: 종목 select(시드된 Exam) → 회차 select(오늘 이후 회차만, "2027-02-14 (D-76)" 형식) → [등록].
  - 목표 제목 = 종목명. 우선순위 입력 없음(기본값).
  - 같은 회차 중복 등록 차단.
- 등록 처리(트랜잭션): Goal 생성 → 해당 Exam의 CurriculumUnit을 sortOrder 순으로 Task로 복사(03 §3 규칙으로 slotType·min/max 부여) → 이번 주 재배분 실행.
- 등록된 목표 목록: 제목, 시험일, D-day, 태스크 수, 총 청크(시간 환산 "총 36시간"), [삭제].
- 하단 [주간표 보기] → `/`.

## 5. 메인 (`/`)

### 5.1 레이아웃

```
┌───────────────────────────────────────────────────────────────┬─────────────────────┐
│ DayAuto   11/30(월) – 12/6(일)      [동기화] 마지막 동기화 09:02 │ 조정안 (n)          │
│                                     [시간대 수정] [목표 관리]   │ ┌─────────────────┐ │
├───────────────────────────────────────────────────────────────┤ │ 사유 한 줄        │ │
│ 주간 캘린더 (월~일, 06:00–24:00, 15분 눈금)                     │ │ 이동 목록         │ │
│  - 외부 일정: 회색                                              │ │ [이대로 진행]     │ │
│  - 학습 배정: 목표별 색, "과목 · 단원", 마이크로/집중 배지       │ │ [다시 배분]       │ │
│  - 조정안 미리보기: 목표 시간에 점선 고스트 블록                 │ │ [원래 일정대로]   │ │
│  - 외부 일정과 겹친 배정: 빨간 테두리 + "겹침"                   │ └─────────────────┘ │
│                                                               │ 목표 현황           │
│                                                               │ 동기화 기록         │
└───────────────────────────────────────────────────────────────┴─────────────────────┘
```

- 캘린더는 **보기 전용** (드래그·클릭 편집 없음). 이번 주만 표시 (주 이동 없음).
- 블록 툴팁/라벨: `[토익] RC Part 5 문법 핵심 개념 · 45분`.

### 5.2 진입 시 자동 처리

순서가 중요하다. **동기화가 먼저, 배분이 나중**이다.

1. `ensureWeekSynced()`: `lastSyncedAt`이 없거나 이번 주 시작 이전이면 동기화 1회 자동 실행. (그 외에는 버튼으로만)
2. 이번 주 배정이 없으면 주간 배분 실행 (04 §4.1).

`ensureWeekSynced()`는 **모든 배분 실행 직전**(시간대 저장, 목표 등록·삭제 포함)에도 호출한다. 외부 일정을 모르는 상태에서 배분하면 회사 일정 위에 학습이 깔리고, 다음 동기화 때 그 전부가 "충돌"로 잡혀 조정안이 쏟아진다.

### 5.3 [동기화] — Server Action `syncCalendar()`

결과를 우측 "동기화 기록"에 맨 위로 추가 (화면 상태로만, DB 저장 안 함):
`09:02 새 일정 1건 · 변경 0건 · 삭제 0건 · 학습 일정과 겹침 2건 → 조정안 1개`

실패 처리:

| 상황                   | 동작                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- |
| access token 만료      | refresh token으로 갱신 후 1회 재시도 (Account 테이블 갱신)                    |
| 갱신 실패·401/403      | "구글 연결이 만료되었습니다. 다시 로그인해 주세요." + [다시 로그인]           |
| 429/5xx/타임아웃(10초) | "구글 캘린더를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요." DB 변경 없음 |

### 5.4 조정안 카드 (PENDING 제안마다 1장, 생성 순)

- 제목: `'{트리거 일정 제목}' 일정 변경`
- 본문: 사유 한 줄 (04 §7)
- 이동 목록: `[목표] 과목 · 단원  월 11/30 20:00 → 화 12/1 21:30` / 배치 불가는 `→ 이번 주 배정 해제`
- 카드에 마우스를 올리면 캘린더에 고스트 블록 강조.
- 버튼 3개 (REQ-ES-04, ES-05), 처리 중에는 3개 모두 비활성:

| 버튼            | Server Action            | 결과                                                                                         |
| --------------- | ------------------------ | -------------------------------------------------------------------------------------------- |
| [이대로 진행]   | `acceptProposal(id)`     | 재검증 → 배정 이동/해제 → `ACCEPTED` → 토스트 "주간표에 반영했습니다"                        |
| [다시 배분]     | `reallocateProposal(id)` | 기존 `SUPERSEDED`, 새 안으로 카드 교체 / 대안 없으면 토스트 "더 이상 다른 배분안이 없습니다" |
| [원래 일정대로] | `rejectProposal(id)`     | `REJECTED`, 배정 그대로 → 토스트 "기존 일정을 유지합니다"                                    |

모든 액션은 서버에서 **제안 소유자 = 로그인 사용자**인지, 상태가 `PENDING`인지 확인한다.

### 5.5 목표 현황 (간단)

목표별: 제목, D-day, 잔여 청크(시간 환산), 이번 주 배정 청크, 긴급도(소수 1자리), 이번 주 미배정 청크(있으면 주황).

## 6. 서버 계층 구성

- `src/server/actions/*.ts` (`"use server"`): 세션 확인 → 서비스 호출 → `revalidatePath("/")`. 비즈니스 로직 없음.
- `src/server/services/*.ts`: DB 읽기 → 엔진 호출 → DB 쓰기를 **하나의 트랜잭션**으로. 엔진 입력 변환(Prisma 모델 → 엔진 타입)도 여기서.
- `src/server/calendar/google.ts`: `listWeekEvents(userId, range)` — Account에서 토큰 읽기, 만료 시 `https://oauth2.googleapis.com/token`으로 갱신, `GET https://www.googleapis.com/calendar/v3/calendars/primary/events?timeMin&timeMax&singleEvents=true&showDeleted=true&maxResults=250` (페이지네이션 처리), 10초 타임아웃.
- 캘린더 범위는 **primary 캘린더 하나**.
