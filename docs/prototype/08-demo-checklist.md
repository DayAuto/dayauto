# 08. 시연 체크리스트

11/30(월) 시연용 체크리스트. 근거는 06 문서 N-06~N-08, N-15. 시나리오 원문은 [01 문서 §1](./01-goal-and-scope.md).

시연 환경은 **로컬(`http://localhost:3000`)** 이다. 배포는 범위 밖이다.

## 시연 데이터 준비 (시연 1주~며칠 전)

- [ ] 앱에서 **목표 2개 등록**: 토익(TOEIC) 12월 회차, 산업안전기사 필기 2027년 1회 (`/setup/goals`)
- [ ] 생활 시간대 저장 (기본값: 출근 07:30–08:15 / 점심 12:30–13:00 / 퇴근 18:30–19:15 / 퇴근 후 20:00–23:00, 월~금)
- [ ] **시연 주(11/30~12/4)에 구글 캘린더로 회사 일정 2~3개 등록**. 주간표에 회색 블록으로 보여 "회사 일정이 있는 주"로 보이게 하는 용도다.
  - 예: 화 14:00–15:00 주간 회의 / 수 10:00–12:00 고객사 미팅 / 목 16:00–17:30 프로젝트 리뷰
  - **생활 시간대(위 4개)와 겹치지 않는 업무 시간에** 넣는다. 겹치면 시연 전부터 조정안이 뜬다.
  - **"팀 회식"은 미리 넣지 않는다.** 시연 중에 추가하는 일정이다.
- [ ] 시연 데이터가 준비되면 주간표에 월~금 학습 블록이 보이는지, 월요일 퇴근 후(20:00~)에 집중 블록이 있는지 확인한다.

## DEMO_NOW 리허설 주의

- [ ] `DEMO_NOW=2026-11-30T09:00:00+09:00`를 쓰면 앱은 **11/30이 속한 주(11/30~12/6)를 "이번 주"로 보고, 구글 캘린더도 그 주 범위로 조회**한다. **리허설용 일정(회식 등)도 반드시 11/30~12/6 안에 넣는다.** 실제 오늘이 속한 주에 넣으면 동기화에 잡히지 않는다.
- [ ] 리허설 회식은 **11/30(월) 19:00–23:00**으로 넣는다. (DEMO_NOW 기준 "오늘"이 11/30이다.)
- [ ] `.env.local`에 `DEMO_NOW`를 추가하거나 바꾸면 **dev 서버를 재시작**한다.
- [ ] 리허설이 끝나면 구글에 넣은 **리허설용 일정을 삭제**하고 `DEMO_NOW`를 제거한다.

## 시연 1~2일 전

- [ ] 시연 계정으로 앱에서 **재로그인**한다. 구글 OAuth 테스트 모드의 refresh token은 **7일 뒤 만료**된다. (재로그인 시 DB 토큰은 `events.signIn`에서 갱신된다 — N-07)
- [ ] 시연 계정이 구글 Cloud 콘솔 OAuth 동의 화면의 **테스트 사용자**에 등록되어 있는지 확인한다.
- [ ] 로그인 동의 화면에서 **캘린더 항목을 해제하지 않았는지** 확인한다. (해제하면 동기화가 403으로 실패한다)

## 시연 전날

- [ ] **Supabase 무료 프로젝트가 활성 상태인지 확인**한다. 7일간 미사용이면 일시정지된다. 일시정지되어 있으면 대시보드에서 복구하고 `npm run dev`로 로그인까지 확인한다.
- [ ] 시연 환경에서 `npm run dev`로 주간표와 [동기화]까지 한 번 실행해 본다. (오류 메시지가 없어야 한다)
- [ ] 시연 PC의 시각·타임존이 **KST(Asia/Seoul)** 인지 확인한다. (주간표는 브라우저 타임존 기준으로 그려진다 — N-26)

## 시연 당일

- [ ] `.env.local`의 **`DEMO_NOW`를 제거(또는 주석 처리)** 하고 dev 서버를 재시작한다. (남아 있으면 오늘 날짜가 11/30이 아닌 값으로 고정된다)
- [ ] **회식 일정 없이** 앱을 먼저 한 번 열어 동기화·주간 배분을 끝낸다. (회식을 먼저 넣으면 첫 진입 자동 동기화가 회식을 배분에 반영해 조정안이 뜨지 않는다.)
- [ ] 주간표에 학습 블록과 회사 일정(회색)이 보이고, 우측 "조정안 (0)"인지 확인한다.
- [ ] 시연 계정 로그인 상태, 구글 캘린더 탭(별도 탭)을 미리 열어 둔다.

## 시연 순서

[01 문서 §1](./01-goal-and-scope.md)과 같다.

1. 구글 캘린더(별도 탭)에 **오늘(11/30) 19:00–23:00 "팀 회식"** 추가
2. 앱에서 **[동기화]** → "새 일정 1건, 학습 일정과 겹침 N건" + 조정안 카드
3. 조정안 카드 확인 (사유 한 줄, 이동 목록, 카드에 마우스를 올리면 고스트 블록 강조)
4. (선택) **[다시 배분]** → 다른 시간대의 새 안으로 교체
5. **[이대로 진행]** → 월요일 저녁 블록이 화요일 이후로 이동, 카드 사라짐
6. (보조) 구글에서 회식 삭제 후 [동기화] → "삭제 감지" 안내만 표시 (되돌림 제안 없음)

## 리셋 방법 (시연 반복·재시연)

먼저 **구글 캘린더의 회식 일정을 삭제하고 앱에서 [동기화]** 해서 삭제를 반영한다. (그대로 두면 회식 시간을 피해 배분되어 시나리오가 재현되지 않는다)

| 방법                   | 절차                                                                                                                                                  | 언제                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 빠른 리셋: 시간대 저장 | `/setup/windows`에서 [저장]을 한 번 누른다. 이번 주 미래 배정을 지우고 재배분하며 대기 중 조정안은 정리된다. (수락했던 이동도 원래 배분으로 돌아간다) | 같은 데이터로 시나리오를 다시 돌릴 때                   |
| 목표 삭제 후 재등록    | `/setup/goals`에서 목표를 삭제하고 다시 등록한다. 시간대·로그인은 유지된다.                                                                           | 목표 데이터까지 다시 만들고 싶을 때                     |
| 전체 초기화            | `npm run db:reset` → `npm run dev` → **다시 로그인** → 시간대 저장 → 목표 등록. `db:reset`은 시드까지 실행하며 계정 정보도 지워진다.                  | 데이터가 꼬였을 때 (개발 DB 전용, 모든 데이터가 삭제됨) |

전체 초기화 후에는 **재로그인**하고 구글 동의 화면에서 캘린더 항목을 해제하지 않는다.

## 문제가 생기면

| 증상                                       | 확인                                                                                                                       |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 목표 등록 화면의 종목 드롭다운이 비어 있다 | `npm run db:seed`                                                                                                          |
| [동기화]에서 "구글 연결이 만료되었습니다"  | 로그아웃 후 다시 로그인 (refresh token 7일 만료)                                                                           |
| [동기화]에서 "불러오지 못했습니다"         | 네트워크·구글 장애. 잠시 후 재시도 (DB 변경 없음)                                                                          |
| 로그인이 "액세스 차단됨"                   | 시연 계정이 구글 테스트 사용자에 없다                                                                                      |
| 페이지가 DB 오류로 열리지 않는다           | Supabase 프로젝트 일시정지 여부, `DATABASE_URL`                                                                            |
| [동기화]해도 조정안이 안 뜬다              | 회식이 학습 시간(퇴근 후 20:00~)과 겹치는지, 회식을 넣기 전에 앱을 한 번 열어 배분했는지, `DEMO_NOW` 주와 일정 주가 같은지 |
